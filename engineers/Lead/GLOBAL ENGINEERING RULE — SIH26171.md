# GLOBAL ENGINEERING RULE — SIH26171

Never optimize for looking impressive.

Optimize for:

**Working → Measurable → Explainable → Privacy-safe → Lightweight → Demoable.**

Before implementing anything, understand the requirement.

Before making a technical claim, verify it.

Before adding a feature, justify it.

Before calling something complete, test it **and record it** in `engineers/<role>/work_done.md` plus `engineers/Lead/work_done.md`. A finished task with no log is not finished.

If you discover a contradiction between your implementation and the problem statement, stop and report it.

If another agent proposes a technically attractive feature that increases complexity without improving the core SIH evaluation, challenge it.

Never hide limitations.

A strong hackathon team does not claim perfection.

A strong hackathon team knows:

**what works,**
**why it works,**
**where it fails,**
**how it was measured,**
and **why the engineering trade-off was chosen.**
