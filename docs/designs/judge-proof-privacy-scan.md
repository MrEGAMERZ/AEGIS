## Problem Statement

In-browser AI (sidebars, AI browsers, agent extensions) processes the live page as the price of convenience. Faces, names, and passwords on the tab become model context. Aegis is a gate in front of that: capture, redact on-device, then let a model see only the sanitized frame.

This week's buyer is not a paying user. It is the SIH selection reviewer who must pass the team to the actual hackathon. They need a prototype they can run, not an architecture talk.

## Status Quo

People mostly do not paste screenshots into ChatGPT. They install an AI Chrome extension or use an AI browser. Lifetime browsing context is processed so they can get answers. That convenience path is the competitor.

2026 category discourse agrees: Gemini sidebar, Edge Copilot, ChatGPT Atlas, and Perplexity Comet read tab contents and send them to a model. Security work treats the agent as a cross-origin data pipe. "Local-first" tutorials often still mean "our UI, their API."

## Recommended Approach

**A — Judge-proof Privacy scan.**

The pipeline already exists. The hole is an unmeasured live Chrome run on TP08. Selection is a repeatable demo, not more architecture.

### Two tickets (do not merge)

1. **Measure (can fail).** The **author/operator** completes steps 0–7 and fills the one-page log. Failure is allowed. Do not use the close-out subject on this run.
2. **Close-out (must pass).** A **different** person, who did not write the code and was not on the measure run, takes the mouse at step 5 (badge already green). Uncoached. Receipt gates met. Scan finished ≤ 120 s including first NER compile. Only then is the live-Chrome hole closed.

### Go/no-go if the rubric scores an agent

Answered on **day 0**, before the measure ticket (see Target User). Not a close-out gate.

- If Privacy scan suffices: close-out is steps 5–7 only.
- If an agent click is required: **Run Agent** is in scope from day 0. Use the existing runbook path (Ollama pre-warm). New estimate. Do not invent a new agent UI. Do not silently fold it into S.

### First-pass implementation order (coding is a later session)

0. Day 0: rubric go/no-go (Privacy scan vs Run Agent).
1. `bash scripts/build-dist.sh`. Verify NER weights exist in `dist/`. `du -sh dist/` in 65–80 MB band. Edit `DEMO_RUNBOOK.md` so the Judge-demo table matches the override (size + latency).
2. **Measure:** author loads unpacked from `dist/`, enables file URLs, opens TP08, waits for green face badge, clicks Privacy scan, fills the log. Hard fail the *scan* if receipt gates unmet or not finished at 120 s. The *ticket* can still record that failure. Note whether the scan was silent > 15 s.
3. Before close-out: ship hung-scan progress copy if measure was silent > 15 s (required even on a passing receipt). Code other classified defects. Re-estimate if the defect is WASM/NER runtime or inject.
4. **Close-out:** a different teammate takes the mouse at step 5. No talking. Pass only if receipt gates met in ≤ 120 s.

|---|---|---|

| Fields masked | `receipt.masked.passwordFields` (shown with spans in `r-fields`) | password field count `> 0` |

**Measure ticket pass:** author log exists, every step 0–7 has pass/fail, hung-after-N-seconds filled if it hung. Failure is allowed.

**Close-out pass:** a different, uncoached person completes steps 5–7 on a face-badge-green popup; receipt gates met; scan finished ≤ 120 s (NER init included).
