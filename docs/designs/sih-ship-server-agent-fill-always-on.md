## Problem Statement

ISRO SIH26171: browser client hides faces, passwords, and names on the device, then a server model reads the cleaned screenshot and returns click/type. Floor demo: one grounded click or type on TP08 after Scan. Multi-step form completion is Days 3–4 (profile fill), not the Day 2 agent loop.

This repo already has the client hide path. It has no `server/` folder. The teammate repo (Awais-17/SIH26) has a local gateway plus form-fill. Always-on overlays are the last slice in a 6-day build plus 2 slip days.

## Demand Evidence

Scored audience: SIH / ISRO panel. Weights: screen context 25%, PII detect 20%, redaction 20%, client resources 20%, end-to-end latency 15%. No named paying user.

## Status Quo

AI sidebars and AI browsers send live page context to a model. ISRO’s required workaround: redact on the client before any network call.

## Target User & Narrowest Wedge

Judge on Chrome. One page: `eval/test-pages/tp08-kitchen-sink-registration.html` (TP08): visible face photo, password and card fields, name/PII text.

Build order (gates, not parallel):

1. Floor: local gateway + Privacy scan + Run Agent on TP08
2. Form-fill from saved profile (five keys only)
3. Always-on DOM covers on TP08 without clicking Scan

## Glossary

- **Scan:** capture, local redact, show preview + Last Privacy Receipt. No server required.
- **Run Agent:** Scan, then POST to the gateway, execute **one** returned action. Multi-step fill is Days 3–4.
- **Mock:** teammate `server/` `--mock`. Deterministic actions, no vision model.
- **Gateway:** teammate `server/` on `http://localhost:8000`. OpenAI-compatible `POST /v1/chat/completions`. Forwards to Ollama unless mock.
- **Ollama:** local vision model behind the gateway (`UPSTREAM_BASE_URL` default `http://localhost:11434/v1`).
- **Always-on:** DOM overlays + a “Protected” cue with no Scan click. Does not send pixels. Does not run BlazeFace every frame.

## Floor data flow

```
TP08 tab
  → content.js DOM_SCAN (password rects, dpr, viewport, field list)
  → background captureVisibleTab
  → offscreen + inference.worker (BlazeFace, NER, password black-fill)
  → receipt.masked.{faces, piiSpans, passwordFields} + sanitizedImage
  → [Run Agent only] POST http://localhost:8000/v1/chat/completions
  → gateway returns one action JSON (schema below)
  → content.js execute that one action
```

**Request (this repo wins):** current `handleCaptureAndSanitize` chat-completions body (`sanitizedImage` + `buildPageStructureForVlm()`, no URL/title). **Response (teammate wins):** `extractAction` at `d4b9c91`. If the gateway rejects the client body, change the client’s message shape to match the gateway; do not change `extractAction`.

**Response (copy teammate `server/index.js` `extractAction` at `d4b9c91`, do not invent):**

| action | required fields |
|---|---|
| `click` | `x` number, `y` number (CSS pixels after DPR handling already in this repo) |
| `type` | `selector` string, `value` string |
| `scroll` | `direction` `up` or `down` |
| `navigate` | `url` string (executor may already have it; Day 2 pass does not require navigate) |
| `done` | `summary` string |

Day 2 pass is `click` or `type` landing on a real TP08 control. `done` without a prior click/type fails the floor.

Extension setting: `vlmEndpoint` default becomes `http://localhost:8000/v1/chat/completions` (today `http://localhost:11434/v1/chat/completions`). `GET /health` must be 200 before Run Agent.

**Gateway start (pinned tree `server/`):**

```
cd server && npm install && npm run start:mock
curl -sS http://localhost:8000/health
```

`package.json` at the pin already has `start:mock` → `node index.js --mock`.

**Mock must be TP08-grounded.** Default canned action for rehearsal:

`{ "action": "type", "selector": "#email", "value": "ananya.krishnan@example.com" }`

Do not mock-type into `#portal-pin`, `#cvv`, `#aadhaar-number`, or `#pan-number`. If copied `server/` mock returns `done` or a generic click first, change that canned branch on Day 1 so Day 2 can pass.

Real mode later: `cd server && npm start` with Ollama already serving. Mock stays the rehearsal default. Ollama model id is whatever the gateway README default is; do not block Day 1 on a specific pull.

Judge load: unpacked `dist/`, enable **Allow access to file URLs**, open TP08 via `file://`. Open popup, wait until **BlazeFace ready (WASM)** is green **before** the 120 s Scan clock. That checkbox is an operator step, not a code task. If Scan still fails after the checkbox, that is an inject defect (re-estimate). Do not switch to http:// mid-demo.

Gateway + Scan + Run Agent. Cut fill and always-on.

Rejected as the whole plan: you asked to include fill and always-on in this window.

Rejected as the whole plan: always-on stays in the window if slip remains.

### C — Sequenced full ship (chosen)

Day 0 measure. Days 1–2 floor. Days 3–4 fill. Days 5–6 always-on. Stop at a red gate. Effort L (human ~6 days + 2 slip). Risk Med if sequenced, High if parallel.

### Days 5–6 — Always-on

Start only if Day 4 passed and slip has not eaten these days.

Detector: same DOM heuristics as today’s password / autocomplete sensitive scan (`scanDOMForSensitiveFields` in `content.js`), plus name/email/tel/autocomplete. Re-run on MutationObserver, **debounced 300 ms**, **max 4 runs / 10 s** per tab. Active tab only. No NER and no BlazeFace in the observer path.

UI: existing orange/black field covers + a small “Protected” cue. Covers are **visual only**: `pointer-events: none` so Run Agent click/type and profile fill still hit the real controls. If a cover must stay clickable for some other reason, hide overlays for the duration of the action and restore after. No pixel capture, no `fetch`, no VLM.

Network assertion: idle always-on on TP08 produces **zero** requests to `:8000` or `:11434` (DevTools Network, filter those hosts).

Faces: still Scan / Run Agent only. Always-on pass does **not** require `faces > 0` without a click.

Pass: open TP08, do not click Scan, password (and listed sensitive) fields covered + cue; covers do not steal clicks (`pointer-events: none`); network assertion holds; idle CPU within +15 pp of Day 2 baseline; Day 2 Run Agent and Day 4 fill still work on the same page. If over cap: TP08-only overlays, not `<all_urls>` observer.
