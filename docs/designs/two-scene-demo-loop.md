## Problem Statement

AGs is a Chrome MV3 extension for SIH26171: redact faces, passwords, and PII on-device before any optional local VLM sees a capture. Scan, vault Fill, and idle DOM covers already exist, but idle never runs on first paint and there is no Protected cue. This week’s reviewer needs a demo that works and a live loop they can see without a Scan click. Company / prompt-firewall work is out.

## What Makes This Cool

Password, card, and ID-keyword fields frost when the page loads — no Scan. Then Privacy Scan frosts the applicant photo and Fill types the saved Ananya profile. Two scenes, one tab.

## Approaches Considered

### Approach A: Load-time covers + Protected chip — insufficient alone

Needed as the Scene 1 slice (first-paint rescan + HUD). Not enough by itself: Scan status and Fill still have to be on the script.

### Approach B: Two-scene demo loop — chosen

Scene 0 seed vault. Scene 1 on-load frost + HUD. Scene 2 Scan photo + Fill Ananya. Pre-warm lives in the existing offscreen worker, not the popup.

### Approach C: Agent-view split — ruled out

Side-by-side “what the agent would see.” Extra surface; implies a second viewport we will not build. Scene 2 stand-in is on-page photo frost + Last Privacy Receipt.

### Idle cover set (locked)

Reuse `scanDOMForSensitiveFields()` in `src/content/content.js`. Idle is **sync DOM heuristics only**. No NER. No BlazeFace. `includeFaces: false`.

Covered:

- `input[type="password"]`
- `input[autocomplete]` containing `cc-number`, `cc-exp`, `cc-csc`, `cc-name`, `cc-type`, `transaction-amount`
- `input`/`textarea` whose id/name/aria-label/placeholder/data-testid tokens match `password`, `pin`, `secret`, `ssn`, `social-security`, `credit`, `card`, `cvv`, `csc`, `otp`, `aadhaar`, `pan`
- `[contenteditable]` with a 16-digit card-shaped sequence

Not covered by idle: name, email, phone, address, and other ordinary profile fields.

**TP08 expected covers after load** (visible, non-zero rect): `#portal-pin`, `#confirm-pin`, `#cvv`, `#card-name`, `#card-number`, `#card-exp`, `#aadhaar-number`, `#pan-number`. HUD `N` equals that overlay count (typically 8 if all are on-screen).

A brief uncovered flash before the 400ms debounce fires is acceptable. Do not change `run_at` this week.

**Password reveal:** out of the demo. Beat 2 is type into `#portal-pin` with `type="password"` still set. Do not add sticky-cover logic this week.

**Scroll/resize:** `content.js` already re-anchors field boxes (`ensureOverlayListeners`). Do not add a second pair. HUD is `position: fixed` in the viewport and does not need re-anchor.

### Protected HUD (locked)

- Id: `sih26171-overlay-hud`.
- **Direct child of `#sih26171-overlay-root`**, sibling of `#sih26171-overlay-fields` and `#sih26171-overlay-faces`. Never inside those layers (`renderFieldOverlays` clears the fields layer innerHTML).
- Repaint HUD at the end of `showRedactionOverlay()`. If `CLEAR_REDACTION_OVERLAY` clears the root, recreate the HUD on the next show (or immediately with N = 0 / hidden).
- CSS: `position: fixed; top: 12px; right: 12px; pointer-events: none; z-index` above field boxes.
- Copy: `Protected · 1 field` / `Protected · N fields` (plural only when N ≠ 1).
- `N` = count of field overlay boxes / `overlayAnchors` only. Do not count the HUD node or face boxes.
- After debounce, if `N = 0`, hide the chip.
- Do not count tab-focus. Tabbing a static form does not change `N`.

### Popup live line (locked)

Element id: `live-protection-status`.

- Popup asks the tab for the current idle field count (reuse `DOM_SCAN` / returned `fields.length`, or `GET_LIVE_PROTECTION` if that is cleaner). Do not guess N.
- When `N ≥ 1`: `Live protection on — covering password, card, and ID fields (not faces).`
- When `N = 0` or the tab did not answer: `Live protection idle — no password/card/ID fields on this page.`
- Never claim faces are live.

### Scene 1 — Live protection (no Scan, no popup required)

On content-script start, call `scheduleSensitiveRescan()` once (today it is only called from `MutationObserver`). Keep the 400ms debounce.

Baseline (already true): idle does not run on first paint. Implementing Scene 1 does **not** wait on re-measuring that; the assignment below is the operator check after the slice ships.

### Scene 2 — Scan + Fill

**Privacy Scan** = existing capture + offscreen sanitize + overlays + receipt. It must not POST to the gateway. If the gateway is down, Scan still succeeds. Do not show `VLM unavailable` / `VLM failed` on Scan. Those strings exist only on Run Agent / leftover VLM fill (`formatVlmOfflineMessage` in `src/popup/popup.js`).

**Operator line for Beat 3:** face detection stays on (default). Privacy Scan then sends `includeFaces: true`. `#applicant-photo` gets a face overlay. If the face toggle was turned off, turn it on before Scan.

**Receipt (TP08, face detection on):** `#last-receipt` (or current Last Privacy Receipt node) must show `masked.faces >= 1` and `masked.passwordFields >= 1`. `piiSpans` may be 0 if NER finds nothing on the sanitized frame.

**Fill Form** after Scene 0: oracle table above.

**Run Agent:** optional. Demo does not fail if Ollama/gateway is down.

### Pre-warm (slice 2 only)

- Popup must not compile WASM. Closing the popup must not abort compile.
- On popup open, send `{ type: "PREWARM_INFERENCE" }` to the background service worker. That message is an **alias** of existing `WARM_WORKER` → `ensureWorkerReady()` / INIT in `src/offscreen/offscreen.js`. Do not add a second ORT/WASM compile path.
- Popup only renders `INIT_PROGRESS` / `INIT_DONE` (already listened).
- Status strings (locked): `Loading on-device models...` while in progress; `On-device ready` on success; `On-device failed` only on a worker/load error. **INIT timeout is not failure** — keep `Loading on-device models...` (optionally `still compiling`) and allow another `WARM_WORKER`. Never `failed` for “still compiling.”
- Operator warmup for Scene 2: open popup, wait until `On-device ready`, then Privacy Scan. No install-time pre-warm.
- Scene 2 time budget after ready: Scan overlays + receipt in **120s** (NER first compile may still count if INIT did not load NER — if so, INIT must also load NER or status must say `Loading NER...` until that finishes). Prefer INIT loads both BlazeFace and NER.

### Pitch if asked why the photo is still visible

Live covers the form fields. Scan covers pixels an agent would photograph. We do not run the face model on idle; that hitchs the tab.
